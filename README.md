<summary><b>📝 My pre-launch security checklist for client projects</b></summary>

<br/>

Before I hand over any web or mobile project, I run through these five checks:

1. **No secrets in the repository.** Keys, tokens and passwords live in environment variables or a secrets manager, never in Git history.
2. **HTTPS everywhere.** A valid certificate, redirects from HTTP, and HSTS enabled.
3. **Security headers set.** At minimum Content-Security-Policy, X-Frame-Options and X-Content-Type-Options.
4. **Dependencies up to date.** Automated alerts turned on, and known vulnerable packages replaced.
5. **Least privilege.** Users, API keys and services get only the access they need, and login and input handling are tested before launch.

Security is easier and cheaper to build in than to bolt on later.
